# Сайт luchistaya-yoga.ru — клуб йоги

Сайт с личным кабинетом, админкой и видеоуроками. Около 10 активных участниц.
Владелец — Любовь, не программистка. Объясняй по-русски, по шагам, без жаргона.

## Стек и инфраструктура

- PHP 8.1 + MySQL 8 + ванильный JS, без фреймворков
- Хостинг Beget, Россия. Это принципиально: персональные данные участниц
  должны храниться на российских серверах
- Путь на сервере: `/home/f/focuspkp/luchistaya-yoga.ru/public_html/`
- База: `focuspkp_yoga`
- Репозиторий на GitHub, рабочая ветка `main`
- Деплой: GitHub Actions + rsync, срабатывает на push в `main`

## Главные правила

- **Push в `main` = выкладка на боевой сайт.** Тестового стенда нет
- Перед push прогонять `php -l` по всем изменённым файлам
- Схему базы менять только вручную через phpMyAdmin. Автоматических миграций
  нет и быть не должно
- **Перед любой миграцией сверять колонки с актуальным дампом базы**, а не с
  `db/schema.sql` и не с папкой `db/migrations`: они расходятся. Миграция
  `0006_add_prodamus_support.sql` на прод никогда не применялась
- Миграцию оформлять файлом в `db/migrations/` и давать пошаговую инструкцию
  для phpMyAdmin — применяет Любовь, не ты
- Перед опасными изменениями просить сделать дамп базы
- **Никогда не коммитить `.claude/worktrees/`** — попав в репозиторий, эти папки
  ломают GitHub Actions с exit code 128
- Дампы базы в репозиторий не класть: в них открытым текстом пароль Kinescope
  и токен Telegram-бота

## Как проверить, что выкладка доехала

```
curl -s https://luchistaya-yoga.ru/version.txt
```

Должен вернуться номер последнего коммита в `main`. Этот файл кладёт сама
выкладка, и она же проверяет его после rsync. Шаги проверки в
`.github/workflows/deploy.yml` не удалять: без них деплой молча не работал
с 9 сентября по 25 ноября 2026 года, и никто этого не замечал.

## Что нельзя сломать

- Действующие участницы не должны терять доступ
- `/trial` и `/trial-extra` открываются без регистрации. Уроки для них заданы
  настройками `trial_lesson_id`, `trial_lesson_id_2`, `trial_lesson_id_3`
- Пароль Kinescope и приветственное видео — глобальные настройки кабинета

## Модель доступа (с 25.11.2026)

- Таблицы `products`, `product_topics`, `user_access`, `orders`
- Единая точка проверки — `has_access()` в `includes/access.php`
- Клуб — продукт со slug `club`, 3000 ₽ в месяц, цена одна для всех
- Тема без продукта не видна никому (fail-closed). Новые темы автоматически
  привязываются к клубу, пока нет раздела «Продукты» в админке
- Старая таблица `subscriptions` пока живёт и дублируется ради отката.
  Не удалять раньше этапа 5

Подробности: `docs/MIGRATION-0007-PRODUCTS.md`
